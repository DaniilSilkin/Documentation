# Спецификация API

Добро пожаловать в документацию по API **Адаптивного помощника** — интеллектуальной системы поддержки клиентов.

## Базовые сведения

API предоставляет доступ ко всем функциям системы:

- База знаний и чат для пользователей
- Дашборд оператора с AI-рекомендациями
- Админ-панель для управления уставом и настройками

### Базовый URL

| Окружение | URL |
|-----------|-----|
| **Локальная разработка** | `http://localhost:5000/api` |
| **Production** | `https://api.support-system.com/api` |

### Формат ответа

Все успешные ответы API обернуты в стандартную структуру:

```json
{
  "success": true,
  "message": "Операция выполнена успешно",
  "data": { ... }
}


В случае ошибки:

{
  "success": false,
  "error": "Описание ошибки",
  "code": 400
}


Аутентификация
API использует JWT токены для аутентификации. Токен передается в заголовке:

text
Authorization: Bearer <access_token>
Также поддерживается аутентификация через cookie (access_token).

Как получить токен:

Выполните запрос POST /auth/login

В ответе получите access_token и refresh_token

Используйте access_token для доступа к защищенным эндпоинтам

Auth
Эндпоинты для аутентификации и управления сессией.

POST /auth/login
Аутентификация пользователя. Вход в систему. При успешной аутентификации возвращает JWT токены.

Тело запроса:

json
{
  "email": "operator@company.com",
  "password": "password123"
}
Успешный ответ (200):

json
{
  "success": true,
  "data": {
    "user": { ... },
    "access_token": "eyJhbGciOiJIUzI1NiIs...",
    "refresh_token": "eyJhbGciOiJIUzI1NiIs..."
  }
}
Ошибка (401):

json
{
  "success": false,
  "error": "Неверный email или пароль",
  "code": 401
}
POST /auth/refresh
Обновление access токена. Используйте refresh_token, чтобы получить новый access_token.

Тело запроса:

json
{
  "refresh_token": "eyJhbGciOiJIUzI1NiIs..."
}
Успешный ответ (200):

json
{
  "success": true,
  "access_token": "eyJhbGciOiJIUzI1NiIs..."
}
POST /auth/logout
Выход из системы. Завершает текущую сессию пользователя.

Требует аутентификации: bearerAuth

Успешный ответ (200):

json
{
  "success": true,
  "message": "Успешный выход"
}
GET /auth/me
Получение информации о текущем пользователе.

Требует аутентификации: bearerAuth

Успешный ответ (200):

json
{
  "success": true,
  "data": {
    "id": 1,
    "username": "operator_ivanov",
    "email": "ivanov@company.com",
    "full_name": "Иванов Иван Иванович",
    "roles": ["operator", "supervisor"],
    "is_active": true,
    "last_login": "2024-01-15T14:30:00Z",
    "created_at": "2024-01-01T10:00:00Z"
  }
}

Admin (Администрирование)
Эндпоинты для администраторов. Требуют аутентификации и прав admin/supervisor.

Управление уставом (/admin/charter)
GET /admin/charter
Получить все правила устава.

POST /admin/charter
Добавить новое правило.

Тело запроса:

json
{
  "rule_code": "COMM_001",
  "rule_title": "Вежливость и уважение",
  "rule_text": "Все сотрудники обязаны общаться вежливо...",
  "category": "communication",
  "priority_level": 10,
  "is_mandatory": true
}
PUT /admin/charter/{rule_id}
Обновить правило.

DELETE /admin/charter/{rule_id}
Удалить правило.

POST /admin/charter/import
Массовый импорт правил из JSON.

Управление пользователями (/admin/users)
GET /admin/users
Получить список пользователей.

POST /admin/users
Создать нового пользователя.

PUT /admin/users/{user_id}

Управление триггерами (/admin/keywords)

Справочник типов данных

Значение	Описание
user	Обычный пользователь
operator	Оператор поддержки
supervisor	Супервизор

Статусы сессии (SessionStatus)
