# Платформизация проекта

## Введение

Платформизация — это стратегия, при которой часть функциональности программного продукта выносится на внешние публичные платформы (PaaS — Platform as a Service). Это позволяет сократить время разработки, снизить затраты на поддержку сложных компонентов и сфокусироваться на ключевой бизнес-логике.

В данном разделе рассматривается возможность замены отдельных компонентов адаптивного помощника на готовые публичные платформы, а также описывается стратегия монетизации и коммерциализации продукта.

---

## 1. Функционал, который можно заменить на платформу

### 1.1 Кандидат на замену

**Кандидат на замену — базовый модуль NLP (Natural Language Processing) и анализа тональности.**

В текущей реализации проекта анализ тональности выполняется с помощью собственной функции `analyze_sentiment`, написанной на Python. Этот компонент работает на основе правил (rule-based) с использованием заранее определённых словарей ключевых слов.

**Почему этот компонент можно заменить:**

| Причина | Объяснение |
|---------|------------|
| **Высокая сложность** | Качественный анализ тональности требует сложных ML-моделей, которые сложно разрабатывать и поддерживать самостоятельно |
| **Доступность готовых решений** | На рынке существуют специализированные платформы, предлагающие анализ тональности как сервис |
| **Экономия ресурсов** | Разработка и поддержка собственной ML-инфраструктуры требует значительных инвестиций |
| **Фокус на уникальной ценности** | Основная ценность проекта — генерация рекомендаций с учётом устава, а не сам анализ тональности |

### 1.2 Что остаётся в проекте

При вынесении NLP-модуля на внешнюю платформу в проекте остаются:

| Компонент | Назначение |
|-----------|------------|
| **Flask-приложение** | Основная бизнес-логика, API endpoints |
| **База данных (PostgreSQL)** | Хранение всех данных |
| **Пользовательские интерфейсы** | Клиентский чат, панель оператора, панель администратора |
| **Генератор рекомендаций** | Формирование ответов с учётом устава |
| **Система аутентификации** | Управление пользователями и ролями |
| **Управление уставом** | Загрузка и индексация корпоративных правил |

## 2. Существующее решение на рынке

### 2.1 Выбранная платформа: Fixorix

**Fixorix** — это готовая российская AI-платформа для клиентской поддержки, предоставляющая функции анализа тональности, определения интента и других NLP-задач в виде сервиса.

**Почему Fixorix:**

| Критерий | Обоснование |
|----------|-------------|
| **Российское решение** | Соответствует требованиям 152-ФЗ о хранении данных на территории РФ |
| **Специализация на поддержке** | Платформа ориентирована именно на задачи клиентской поддержки |
| **Готовая инфраструктура** | Не требует развёртывания и обслуживания собственных ML-моделей |
| **API-интеграция** | Простое подключение через REST API |

### 2.2 Как использовать Fixorix
**Пошаговый процесс интеграции:**

| Шаг | Действие | Описание |
|-----|----------|----------|
| **1** | Перенаправление запроса | Flask-приложение отправляет текст сообщения от клиента в Fixorix через их API |
| **2** | Получение результата | Fixorix возвращает JSON с готовым анализом (тональность, интент, ключевые сущности) |
| **3** | Использование в проекте | `app.py` получает результат и использует его для генерации ответа для оператора с учётом внутреннего устава |
